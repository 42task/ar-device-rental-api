# 四级身份

多商户版本中角色权限受商户归属限制，root 具有平台范围。商户创建、切换、设备和人员调拨见[多商户运行说明](multi-merchant.md)。`admin` 表示管理平台，`adminer` 表示商户管理员。

权限按 `root > adminer > manager > user` 继承。所有身份都保留使用者能力，自行租赁仍须正常支付使用费和押金。

| 能力 | user | manager | adminer | root |
| --- | --- | --- | --- | --- |
| 扫码、租借、支付、查看本人订单和退款进度 | 可以 | 可以 | 可以 | 可以 |
| 登记设备、配置费用和启停、查看管理订单 | 不可以 | 可以 | 可以 | 可以 |
| 确认归还、退押金或全额退款、管理处理中退款 | 不可以 | 可以 | 可以 | 可以 |
| 网页查询系统用户 | 不可以 | 不可以 | 可以 | 可以 |
| 网页切换其他人的 user / manager 身份 | 不可以 | 不可以 | 可以 | 可以 |
| 网页授予、降级或撤销 adminer | 不可以 | 不可以 | 不可以 | 可以 |
| 网页直接授予、替换或降级 root | 不可以 | 不可以 | 不可以 | 不可以 |

adminer 只能管理当前为 user 或 manager 的其他账号，不能修改自己、同级 adminer 或 root，也不能授予 adminer。root 可将其他非 root 账号设为 user、manager、adminer。自己和 root 始终受保护。

网页将每个目标的 `allowedRoles` 与本地规则取交集；服务端仍在事务中重新读取并锁定操作者和目标账号，记录前后身份与变更原因。降为 user 后旧小程序令牌和网页会话不能继续执行管理请求；adminer 降为 manager 后保留设备管理能力，失去身份管理能力。

## 角色拼写迁移

当前角色标识为 `user`、`manager`、`adminer`、`root`。schema 7 将原系统管理员标识 `admin` 更名为 `adminer`，权限层级不变。后端启动迁移时同步更新 `ar_user.role` 和 `ar_role_audit` 中的前后角色，保留账号、审计记录及既有权限。迁移支持重复执行。

发布时需协调 API、独立网页后台与小程序一起使用 `adminer`，并核实 schema 8（含 schema 7 角色拼写迁移）已就绪。管理页面与接口的 `/admin/` 路径、`npm run admin` 维护命令保留原名。此处说明代码中的迁移行为，不代表已经执行线上迁移或发布。

## 唯一 root

新注册固定为 user。root 只通过服务端 `ROOT_PHONE` 匹配微信已验证手机号，或受控维护命令再次核对该已验证绑定后初始化；客户端自报身份、旧 tel 字段、手填号码、裸用户 ID 都不能取得 root。

数据库唯一约束与初始化事务保证全库最多一个 root。已有 root 保留，修改或清空 `ROOT_PHONE` 不自动迁移最高权限。若迁移发现多个旧 root，应停止并要求人工核实，不能静默选择或降级。

手机号绑定与初始化步骤见[后台说明](admin.md)。真实手机号和密钥不进入源码或客户端。

## 资金边界

user 只能读取退款结果，不能自行结束租赁、发起退款或重试退款。manager、adminer、root 扫码后确认实物归还、原因和服务端金额，再选择退押金或全额退款。

退款仍使用订单实付快照、验签、原退款单号和幂等控制；未确认退款成功时设备保持结算占用。身份变化不改变订单金额、不免除付款，也不取消已合法持久化的退款处理。
